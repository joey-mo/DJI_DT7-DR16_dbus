# STM32F407 DBus Receiver — DJI DT7 / DR16

![MCU](https://img.shields.io/badge/MCU-STM32F407IGHx-blue.svg)
![Firmware](https://img.shields.io/badge/STM32Cube%20FW__F4-V1.28.3-03234b.svg)

![Toolchain](https://img.shields.io/badge/toolchain-arm--none--eabi--gcc-orange.svg)

A bare-metal driver for the **DJI DBus** protocol used by the **DT7 transmitter / DR16
receiver**, running on an **STM32F407IGHx**.

The 18-byte DBus frame is captured on **USART3** with a *circular DMA + IDLE interrupt*
scheme, decoded into four stick channels and two switches, and then streamed to a host PC
over **USART6** for live plotting in **VOFA+**.

## Overview

| Item | Value |
| --- | --- |
| MCU | STM32F407IGHx (UFBGA176, custom board) |
| Clock | HSI 16 MHz → PLL (M=8, N=168, P=2) → SYSCLK 168 MHz (AHB 168 / APB1 42 / APB2 84) |
| DBus input | USART3 · `PC11` = RX, `PC10` = TX · 100000 baud · 8 data bits + even parity · 1 stop bit |
| DBus DMA | DMA1 Stream1 / Channel 4 · peripheral → memory · **circular** · byte aligned |
| Frame trigger | USART3 IDLE interrupt (NVIC priority 5) |
| Telemetry out | USART6 · `PG14` = TX · 115200 8-N-1 · 50 Hz |
| Firmware package | STM32Cube FW_F4 V1.28.3 (generated by STM32CubeMX) |
| Build system | CMake + Ninja, `arm-none-eabi-gcc` |

The receiver emits frames continuously (roughly one every 14 ms) with **no header and no
checksum**, so the driver relies on the UART idle line to delimit frames instead of scanning
for a start byte.

## Features

- **Interrupt-driven reception** — a circular DMA transfer writes every incoming byte into a
  90-byte ring buffer (5 frames, ~70 ms of margin) while the CPU stays out of the data path.
- **Ring-buffer wrap handling** — if a frame straddles the end of the DMA buffer, the driver
  splices it back together from two `memcpy` calls before decoding.
- **Full frame decode** — four 11-bit stick channels plus two 2-bit switches, extracted with
  pure bit arithmetic.
- **Corrupt-frame rejection** — the DR16 sticks physically reach about ±660; anything outside
  that range is treated as line noise and the whole channel struct is zeroed.
- **Live telemetry** — a rate-limited (50 Hz) integer-only text stream in VOFA+ *FireWater*
  format, so the receiver can be verified without a debugger or a logic analyzer.
- **No external crystal required** — the clock tree runs from the internal HSI.

## Hardware setup

### Pinout

| Signal | Pin | Peripheral | Configuration |
| --- | --- | --- | --- |
| DBus RX (from receiver) | `PC11` | USART3_RX | AF7, 100000 baud, 8E1 |
| DBus TX (unused) | `PC10` | USART3_TX | AF7 |
| Telemetry TX (to USB-TTL RX) | `PG14` | USART6_TX | AF8, 115200 8-N-1 |
| Telemetry RX (unused) | `PG9` | USART6_RX | AF8 |
| Debug | `PA13` / `PA14` | SWDIO / SWCLK | Serial Wire |

### Wiring

```
DJI receiver ──DBus──▶ [inverter] ──▶ PC11 (USART3_RX)     ┐
                                                           ├── common GND required
USB-TTL adapter RX ◀── PG14 (USART6_TX) ◀──────────────────┘
```

> **DBus is an inverted UART signal.** If your receiver exposes the standard inverted DBus
> output, insert a single-transistor (or dedicated) inverter between the receiver and `PC11`.

## How reception works

1. `dbus_uart_init()` (`Core/Src/dbus_usart.c`) clears any stale IDLE flag, enables the IDLE
   interrupt, sets the USART3 IRQ priority to 5, and starts a **circular** DMA transfer of
   `DBUS_BUF_SIZE` (90) bytes.
2. DMA keeps writing bytes into `dbus_rx_buf[]` and wraps around indefinitely — the transfer
   is never restarted.
3. When the transmitter finishes an 18-byte frame the line goes idle, the IDLE interrupt
   fires, and `uart_receive_handler()` confirms both the flag and the interrupt source before
   dispatching.
4. The callback clears the IDLE flag, derives the current write offset from the DMA counter
   (`NDTR`), snapshots the **last 18 bytes** out of the ring (handling wrap-around), and
   decodes them.
5. `dbus_rx_flag` is set to `1` to signal "a fresh frame is available" to the application
   layer; the main loop clears it.

Because the frame has no header, the driver always parses the *tail* of the ring buffer after
an idle event — that is where the most recently completed frame ends.

## Data format

### DBus frame layout (18 bytes)

The driver parses bytes 0–5; the remaining 12 bytes are not used by this project.

| Field | Bytes | Extraction |
| --- | --- | --- |
| `ch0` | 0–1 | `(b[0] \| (b[1] << 8)) & 0x07FF` |
| `ch1` | 1–2 | `((b[1] >> 3) \| (b[2] << 5)) & 0x07FF` |
| `ch2` | 2–4 | `((b[2] >> 6) \| (b[3] << 2) \| (b[4] << 10)) & 0x07FF` |
| `ch3` | 4–5 | `((b[4] >> 1) \| (b[5] << 7)) & 0x07FF` |
| `sw1` | 5 | `(b[5] >> 6) & 0x03` |
| `sw2` | 5 | `(b[5] >> 4) & 0x03` |

### Decoded values

| Field | Meaning | Raw range | Stored as | Range in practice |
| --- | --- | --- | --- | --- |
| `ch0` | Right stick, horizontal | 0 – 2047 | `raw − 1024` | ±660, centred at 0 |
| `ch1` | Right stick, vertical | 0 – 2047 | `raw − 1024` | ±660, centred at 0 |
| `ch2` | Left stick, horizontal | 0 – 2047 | `raw − 1024` | ±660, centred at 0 |
| `ch3` | Left stick, vertical | 0 – 2047 | `raw − 1024` | ±660, centred at 0 |
| `sw1` | Right switch | 0 – 3 | as-is | 1, 2 or 3 |
| `sw2` | Left switch | 0 – 3 | as-is | 1, 2 or 3 |

The public interface is deliberately small:

```c
typedef struct {
    int16_t ch0, ch1, ch2, ch3;  /* sticks, centred at 0 */
    uint8_t sw1, sw2;            /* switches, 1 / 2 / 3 */
} rc_info_t;
```

`rc` holds the latest decoded frame, and `dbus_rx_flag` is set once per decoded frame.

## Live telemetry

`RC_Monitor_Task()` (`Core/Src/rc_monitor.c`) prints one line per frame in **VOFA+ FireWater**
format on USART6 at 50 Hz:

```
ch0,ch1,ch2,ch3,sw1,sw2\n
```

Example output:

```
-23,412,-1005,7,1,2
-23,414,-1006,7,1,2
```

Call it from the main loop — the function rate-limits itself, so calling it every iteration is
fine:

```c
while (1)
{
    RC_Monitor_Task();
}
```

To view the data:

1. Connect `PG14` to the RX pin of a USB-TTL adapter (and connect grounds).
2. Open **VOFA+**, add a data source on the adapter's COM port at **115200-8-N-1**.
3. Select the **FireWater** protocol — six curves appear.

The output is intentionally integer-only: the project links with `--specs=nano.specs`, and
newlib-nano has no floating-point `printf`. The channel values are integers to begin with, so
nothing is lost.

## Building

Requirements:

- CMake ≥ 3.22
- Ninja
- `arm-none-eabi-gcc` on `PATH`

STM32CubeCLT ships all three, which is the easiest way to get a working toolchain on Windows.

```bash
cmake --preset Debug
cmake --build --preset Debug
```

The output lands in `build/Debug/`:

| Artifact | Description |
| --- | --- |
| `dbus.elf` | Executable image (debug symbols in the `Debug` preset) |
| `dbus.map` | Linker map file |

For an optimised build, use `--preset Release` (`-Os`, no debug info). The GCC flags live in
`cmake/gcc-arm-none-eabi.cmake`, and the linker script is `STM32F407XX_FLASH.ld`.

## Flashing

With OpenOCD and an ST-Link probe:

```bash
openocd -f st_nucleo_f4.cfg -c "program build/Debug/dbus.elf verify reset exit"
```

Or with the STM32CubeProgrammer CLI:

```bash
STM32_Programmer_CLI -c port=SWD -w build/Debug/dbus.elf -v -rst
```

`st_nucleo_f4.cfg` is the ST-Link configuration generated for NUCLEO-F4 boards; adjust it if
you use a different probe.

drop the `RC_Monitor_Task()` call from `main()`.

## Regenerating with STM32CubeMX

The project is generated from `dbus.ioc` (STM32CubeMX, firmware package
**STM32Cube FW_F4 V1.28.3**, target toolchain **CMake**). All hand-written code lives inside
`/* USER CODE BEGIN ... */` / `/* USER CODE END ... */` blocks, so regenerating the project
re-creates `main.c`, `usart.c`, `dma.c`, the linker script and the HAL sources without
touching the driver logic.

If you re-run CubeMX, keep the peripheral settings identical:

- USART3 — asynchronous, 100000 baud, 9-bit word length with even parity, 1 stop bit
- USART3 RX — DMA1 Stream1 / Channel 4, circular, byte-aligned
- USART3 global interrupt — enabled
- USART6 — asynchronous, 115200 baud, 8-N-1
- System — SysTick time base

## Notes and caveats

- **Parity and error interrupts are deliberately masked.** `HAL_UART_Receive_DMA()` enables
  `PEIE`/`EIE`, and `HAL_UART_IRQHandler()` treats a parity/framing/noise/overrun error as
  fatal: it calls `UART_EndRxTransfer()` and aborts the DMA transfer. Since this project starts
  reception exactly once and has no restart path, one noisy byte would permanently kill the
  receiver. `dbus_uart_init()` therefore clears both bits; the error flags are still cleared
  when the IDLE handler reads `SR` and `DR`. If you need error recovery, add an explicit
  re-arm routine and re-enable them.
- **Clock source is HSI**, not an external crystal — the PLL is fed from the internal 16 MHz
  oscillator, so the baud rate accuracy depends on HSI tolerance. It has proven sufficient for
  100 kbaud DBus, but an HSE is the safer choice for long-term reliability.
- **`dbus_rx_flag` is application-level only.** It is set on every decoded frame and currently
  just cleared in the main loop; it is the intended hook for a control loop.
- **Only 4 channels + 2 switches are parsed.** The last 12 bytes of the frame are ignored; if
  you need the additional channels some receivers pack there, extend `rc_callback_handler()`.
- The telemetry transmit is **blocking** with a 10 ms timeout. It is fine at 50 Hz, but move it
  to DMA or IT mode before raising the rate.
